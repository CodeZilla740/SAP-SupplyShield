00 / READ THIS FIRST

What you will build

SupplyShield detects a simulated port closure, finds affected temperature-sensitive medical shipments, calculates stockout exposure, compares recovery scenarios, applies cold-chain and supplier rules, and asks a planner to approve the safest recommendation.

Hackathon-safe promise: every number shown in the demo comes from HANA data and deterministic CAP logic. AI interprets and explains; it never invents cost, ETA, stock, or compliance results.

Step 3 — Freeze the one demo scenario

Use one event only: Cyclone Varun closes Chennai Port. Three shipments are impacted. The winning scenario reroutes via Krishnapatnam Port, prioritizes vaccine shipment SH-2048, saves 17 hours, adds a known cost, and passes 12 rules.

  • Do not add real-time weather until the core flow works.
  • Do not attempt live S/4HANA integration unless credentials and documented APIs are supplied.

  • Do not let the model calculate numeric business values.

Acceptance criteria

  1. One click starts the simulation.
  2. Three impacted shipments appear in under five seconds.
  3. At least three recovery scenarios are compared.
  4. An unsafe cold-chain option is visibly rejected.
  5. A human approves the recommended option.
  6. The complete decision trace is queryable in HANA.

04 / PHASE 3 — CAP SERVICES & AGENTS

Build a deterministic agent workflow

Expose these OData actions

service SupplyService { entity Shipments as projection on db.Shipments; entity Disruptions as projection on db.Disruptions; entity Scenarios as projection on db.Scenarios; entity AuditEvents as projection on db.AuditEvents; action runSimulation(eventID: UUID) returns SimulationResult; action approveScenario(scenarioID: UUID, note: String) returns ApprovalResult; }

Implement five bounded “agents” as normal functions

  1. Sensing agent: validates event fields and maps severity from a fixed matrix.
  2. Impact agent: spatially/relationally maps event → routes → shipments → inventory.
  3. Scenario agent: creates wait, reroute, transfer, and supplier options from known master data.
  4. Logistics agent: calculates ETA, cost, allocation, and stockout outcome.
  5. Compliance agent: checks product temperature range, carrier approval, telemetry, supplier approval, and route capability.
Orchestrator order: validate → sense → impact → generate → calculate → enforce rules → rank feasible options → optionally ask AI for grounded explanation → persist audit → return response.

Audit every step

Generate one correlation ID per simulation. For every agent, store: timestamp, version, input record IDs, deterministic output, duration, pass/fail state, and error message. Store hashes rather than secrets or full prompts containing sensitive data.

Hard-rule pseudocode

function checkScenario(scenario, product, carrier) { const checks = [ { code: 'TEMP_RANGE', pass: scenario.minTemp <= product.minTemp && scenario.maxTemp >= product.maxTemp }, { code: 'CARRIER_APPROVED', pass: carrier.approved === true }, { code: 'TELEMETRY', pass: carrier.liveTemperatureTelemetry === true }, { code: 'MAX_TRANSIT', pass: scenario.hours <= product.maxTransitHours } ]; return { checks, feasible: checks.every(c => c.pass) }; }

Error handling

  • If a required record is missing, return a visible “Data incomplete” state; never assume a value.
  • If AI fails, keep the computed recommendation and show a deterministic explanation.
  • If HANA write fails, do not allow approval; show “Audit persistence failed”.
  • Make simulation idempotent: repeated clicks for the same event should not create duplicate active incidents.
05 / PHASE 4 — SAP AI LAUNCHPAD

Add AI safely, only if entitled

What AI is allowed to do

Use AI only for (1) extracting event type/location/time from an unstructured alert and (2) turning already-computed facts into a concise planner explanation. AI must not calculate risk, ETA, stock, cost, rule pass/fail, or select records.

Setup path

  1. Open AI Launchpad and select your resource group/workspace.
  2. Find Generative AI Hub or the model library. Select a small chat model available in your tenant.
  3. Create a deployment and wait for RUNNING/HEALTHY status.
  4. In BTP, create the required service key or destination according to the hackathon-provided instructions. Never paste credentials into source code.
  5. Bind the AI service to the CAP application and read credentials from the service binding.
  6. Call AI from CAP only; never call it directly from the browser.

Grounded explanation prompt

SYSTEM: You explain a medical supply-chain recommendation. Use only the FACTS JSON. Do not invent values. Do not change the selected scenario. If a fact is missing, say "not available". Use under 90 words. FACTS: { event, affectedShipments, selectedScenario, alternatives, ruleChecks } OUTPUT JSON: { "summary": "", "why": ["", ""], "assumptions": [""], "warning": "" }

Validate the output

  1. Require valid JSON; reject prose outside the schema.
  2. Check that every number in AI output also occurs in the supplied facts.
  3. Render AI text under an “AI-generated explanation” label.
  4. Log model/deployment ID, prompt version, latency, and response status.
If no model deployment is available: produce the explanation from CAP string templates. Say “deterministic explanation generator” in your presentation. Do not claim generative AI or fake an AI Core call.

07 / PHASE 6 — HUMAN APPROVAL

Connect SAP Build Process Automation

If Business Process is available in Build Lobby

  1. Build Lobby → Create → Business Process.
  2. Name it SupplyShield Recovery Approval.
  3. Create process inputs: event ID, scenario ID, summary, cost, saved hours, rule-check JSON, requester.
  4. Add an Approval Form with Approve and Reject outcomes.
  5. Add read-only fields for evidence and a required note on rejection.
  6. Configure recipients using the hackathon user or a planner group.
  7. On approval, call the CAP approveScenario action through a destination/API trigger.
  8. On rejection, update scenario state and write the rejection audit event.
  9. Release and deploy the process; copy its API trigger details into a secure BTP destination/service binding.

If Process Automation is not entitled

Use the SAPUI5 approval dialog and CAP Approval entity. Enforce authorization in CAP, write immutable audit records, and present it as the “in-app SAP approval fallback”. This remains SAP-only and demonstrates the correct governance pattern.

Approval state machine

ANALYZING→REVIEW_REQUIRED→APPROVED
or REJECTED→SIMULATED_EXECUTION→CLOSED
Never claim live logistics execution. The final action must read “Simulate execution” unless you truly have an authorized transactional SAP system integration.

Authorization minimum

  • Viewer: read dashboard and audit.
  • Planner: start simulations and propose options.
  • Approver: approve/reject recovery plans.
  • Admin: change rules and reference data.

Pre-demo resilience

  • Seed/reset endpoint restores the known scenario.
  • A local/BAS preview fallback is ready.
  • A 90-second screen recording is downloaded offline.
  • PDF screenshots of the audit and approval result are ready.
  • No credentials, personal data, or internal URLs appear on screen.

Observability

Use one correlation ID from alert through approval. Show response time for each agent, HANA persistence status, AI call status, and workflow status. For a hackathon, this trace is often more convincing than adding another feature.

10 / FINAL SHOWCASE

Your 5-minute winning demo script

0:00–0:35 — Stakes

“A cyclone closes Chennai Port. Temperature-sensitive vaccines and insulin are delayed. A planner has hours—not days—to prevent stockouts without violating cold-chain policy.”

0:35–1:05 — Start the event

Click Run disaster simulation. Point out that the alert is classified and linked to HANA business records, not answered from model memory.

1:05–2:00 — Show multi-agent reasoning

Walk down the live agent trace: sensing, impact, scenario planning, logistics calculation, and compliance. Open the three impacted shipments and the 31-hour earliest stockout.

2:00–2:50 — Compare options

Show the baseline 26-hour delay, safe reroute at 9 hours, transfer option at 13 hours, and rejected unapproved carrier. Say: “AI explains; deterministic SAP logic decides whether an option is safe.”

2:50–3:35 — Human governance

Open the approval. Show all 12 rules and assumptions. Approve. Point out planner identity, timestamp, and decision note in the audit trail.

3:35–4:20 — SAP architecture

“SAPUI5 provides the Fiori experience; CAP orchestrates bounded agents; HANA Cloud stores enterprise facts and the audit; AI Core produces grounded explanations; Build Process Automation governs approval; Work Zone is the role-based entry point.”

4:20–5:00 — Value and close

“SupplyShield turns fragmented disruption response into an explainable, policy-safe decision in minutes—while keeping a human accountable for every consequential action.”

Strong closing line: “We are not replacing the planner. We are giving the planner a faster, safer and fully traceable way to act.”
